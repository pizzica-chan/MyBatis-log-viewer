# MyBatis Log Viewer (mlv)

Java アプリケーションのログファイルから **MyBatis の SQL 実行ログ**（Preparing / Parameters / Total / Updates）を抽出し、Web UI で **検索・統計・詳細表示** するローカル専用ツールです。

## 機能

- ディレクトリ配下のログファイルを再帰探索し、MyBatis SQL ブロックをインデックス化
- SQL 一覧のフィルタ検索（mapper / SQL 種別 / SQL 文 / パラメータ / elapsed / 日時 / grep）
- 含む文字列で一覧の行を 3 色（黄・緑・ピンク）にハイライト（表示のみ。複数に一致した行は番号の小さい欄の色。入力した語はブラウザに保存され、リロードしても残る）
  - grep はブロック全文が対象。ログファイルを読み出せない場合（検索中に削除された等）はエラーになり、黙って結果が欠けることはありません
- 検索条件をツールホーム直下の JSON に保存し、名前を付けて呼び出せる
- 統計ダッシュボード（SQL 種別別件数、mapper 別 TOP、遅い SQL ランキング）
- 行クリックで SQL 全文・パラメータ・生ログブロックを表示
- SQLite インデックスを `tmp/mlv/` に永続化（2 回目以降は高速起動）

## 前提

- **Docker で動作確認（おすすめ）:** [Docker Desktop](https://www.docker.com/products/docker-desktop/)（ホストに JDK/Maven 不要）
- **ローカル開発:** JDK 8 以上（ビルド時は `javac` を含む JDK）、Maven 3.6 以上（ビルド時）

## ビルド

```powershell
cd D:\workspace\MyBatis-log-viewer\mlv-java
mvn -q clean package
```

成果物: `mlv-java\target\mlv-java.jar`

## 起動

```powershell
java -jar mlv-java\target\mlv-java.jar
```

または `start.bat` を実行（JAR 未ビルド時は自動ビルド → ブラウザ起動）。

ブラウザで http://127.0.0.1:8767 を開きます。

```powershell
java -jar mlv-java\target\mlv-java.jar --dir samples --port 8767
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--dir` | 起動時に読み込むログディレクトリ | — |
| `--host` | 待ち受けアドレス | `127.0.0.1` |
| `--port` | 待ち受けポート | `8767` |

## Docker で動作確認（ローカル）

JDK/Maven をインストールせず、コンテナだけでサンプルログの閲覧まで試せます。

### ワンクリック起動（おすすめ）

1. [Docker Desktop](https://www.docker.com/products/docker-desktop/) をインストールする。
2. リポジトリ直下の **`docker-up.bat`** をダブルクリック（または `scripts\one-click-up.cmd`）。

Docker Desktop が止まっていれば **自動起動・待機**（最大約 3 分）→ **ビルド** → **起動** → **ブラウザで http://localhost:8767 を開く** まで一気に実行されます。`samples/` のログは自動読み込みされます。

| 操作 | コマンド |
|------|----------|
| 起動 | `docker-up.bat` |
| 停止 | `docker-down.bat` |
| ソース変更の反映 | `scripts\one-click-restart.cmd` |
| ログ追従 | `.\scripts\one-click-up.ps1 -FollowLogs` |

### 手動（docker compose のみ）

**Docker Desktop を先に起動**してから、リポジトリ直下で実行します。

```powershell
docker compose up --build -d
docker compose ps
docker compose logs -f app
docker compose down
```

### マウントと環境変数

| 項目 | 説明 |
|------|------|
| `./samples` → `/app/logs/samples` | サンプルログ（読み取り専用）。起動時に `--dir` で自動読み込み |
| `./tmp` → `/app/tmp` | SQLite インデックスの永続化 |
| `./mlv-saved-searches.json` → `/app/mlv-saved-searches.json` | 検索条件の永続化（`MLV_HOME` 直下） |
| `MLV_LOG_DIR` | ホスト側のログディレクトリを差し替え（例: `$env:MLV_LOG_DIR="C:\logs\app"`） |
| `MLV_HOME=/app` | コンテナ内のリポジトリルート（インデックス・検索条件の基準） |

検索条件ファイルがホスト側に無いと Docker がディレクトリを作るので、`docker-up.bat` は空の JSON を先に作ります。`docker compose` だけ使うときは、同じファイルを先に置いてください。

**ホストポート:** 既定は **`127.0.0.1:8767`**（ループバックのみ）です。競合する場合は `docker-compose.yml` の `ports` を `"127.0.0.1:18767:8767"` のように変更してください。`127.0.0.1:` を外すと LAN 全体に公開されます。

**注意:** ローカル検証専用です。認証機構を持たず、`/api/browse` で任意ディレクトリの列挙、`/api/load` で任意ディレクトリのインデックス化ができるため、`127.0.0.1` 以外に公開しないでください。

### 検索条件の保存

「保存した検索条件」から、いまの条件に名前を付けて保存できます。保存先は **ツールホーム直下** の `mlv-saved-searches.json` です（`MLV_HOME`。未設定時はリポジトリ直下）。実際に読み書きしているパスは、ダイアログの「保存先」に表示されます。

条件に含まれる正規表現は **文字列として** 保存・読み込みします。ファイルを読んだ時点ではマッチもコンパイルも行いません（検索を実行したときだけ正規表現になります）。

手で JSON を編集する場合、正規表現の `\` は JSON の規則で `\\` と書いてください（例: `\d+` → `"\\d+"`）。項目が 1 件だけ壊れていても、読める件はそのまま使えます（壊れた件は次に保存したときにファイルから消えます）。ファイル全体の JSON が壊れているときは読み込めません。

保存できる条件は 200 件までです。手編集で 200 件を超えたファイルは、読み込みは 200 件までで打ち切り、そのままでは保存・削除ができません（書き戻すと読み込めていない条件が消えるため）。ファイルを直接編集して減らしてください。

「適用」は条件を入力欄へ入れるだけで、検索は実行しません（「検索」を押したときに実行します）。

## 対象ログ形式

MyBatis 3 標準 DEBUG 出力（SLF4J / Logback 等）:

```
2026-06-15 00:19:11.705[thread][DEBUG][com.example.mapper.UserMapper.selectById] - ==>  Preparing: SELECT ...
2026-06-15 00:19:11.706[thread][DEBUG][com.example.mapper.UserMapper.selectById] - ==> Parameters: 1(Long)
2026-06-15 00:19:11.708[thread][DEBUG][com.example.mapper.UserMapper.selectById] - <==      Total: 1
```

Java ログヘッダは Tomcat 形式 `[Thread][LEVEL][Logger(FQCN)]` および旧形式に対応しています（既定書式）。

SQL ブロックを囲むアプリログ側の前置き（日時・レベル・ロガー・スレッド）は、
以下の書式へ切り替えられます。SQL ブロック自体の書式は MyBatis が決めるため対象外です。

| 書式 | 例 |
|------|-----|
| `spring-boot` | `2026-06-15 00:19:11.705  INFO 12345 --- [main] c.e.Mapper : ==>  Preparing: ...` |
| `logback` | `2026-06-15 00:19:11,705 DEBUG [main] com.example.Mapper - ==>  Preparing: ...` |
| `iso8601` | `2026-06-15T00:19:11.705 DEBUG [main] com.example.Mapper - ==>  Preparing: ...` |
| `tomcat-juli` | `15-Jun-2026 00:19:11.705 FINE [main] com.example.Mapper.selectById ==>  Preparing: ...` |

既定は自動判定で、先頭ファイルの冒頭 500 行から最もよく一致する書式を選びます。
判定結果は画面の概要行に出ます。外れた場合はログディレクトリ欄のセレクトで
明示指定できます（CLI は `--format <id>`）。書式を変えるとインデックスは作り直されます。
同時に読み込むファイルはすべて同じ書式である前提です。

### 書式を自分で定義する

上の書式に無い前置きのログは、正規表現で書式を自分で定義すると読めるようになります。
**中身の管理は利用者の責任**です。

**画面から登録できます。** ログディレクトリ欄の **書式の管理...** を開くと、一覧・登録・
編集・削除ができます。ダイアログには **書き方ガイド**（よく使う部品をクリックで差し込める）と
**この行で試す**（ログの 1 行を貼ると、各項目に何が取れるかを返す）があります。

保存先は **ツールホーム直下の `mlv-log-formats.txt`** です（`MLV_HOME`。未設定時は
リポジトリ直下）。実際のパスはダイアログの「保存先」に出ます。**このファイルを直接編集
してもかまいません**。画面から入れても手で書いても、同じ検査を通ります
（[docs/mlv-log-formats.example.txt](docs/mlv-log-formats.example.txt) が雛形です）。

```
[pipe]
name = 縦棒区切りの形式
pattern = ^(?<ts>[^|]+)\|(?<level>[^|]*)\|(?<thread>[^|]*)\|(?<logger>[^|]*)\|(?<message>.*)$
timestamp = yyyy-MM-dd HH:mm:ss.SSS
```

**取り出す項目**は名前付きグループで指定します。

| グループ | 要否 | 用途 |
|---|---|---|
| `ts` | **必須** | 並べ替えと期間の絞り込み。日付まで含むこと |
| `message` | **必須** | MyBatis の `Preparing:` / `Parameters:` / `Total:` をここから探す |
| `thread` | 任意（実質必須） | SQL ブロックの対応付けの鍵 |
| `logger` | 任意（実質必須） | 同上。mapper 名としても出る |
| `level` | 任意 | 絞り込みに使う |

`message` を必須にしているのは mlv だからです。ここが空だと、**行はすべて読めているのに
SQL が 1 件も見つからない索引**が黙ってできあがります。`thread` と `logger` は必須では
ありませんが、この 2 つでブロックの対応を取っているため、**複数スレッドが動くログでは
必ず入れてください**（入れないと別スレッドの `Preparing` と `Parameters` が混ざります）。

**書式ファイルの決まり**:

- `[id]` で 1 つの書式が始まる。`キー = 値` は最初の `=` だけで区切る
- コメントは**行頭の `#` だけ**。値の途中の `#` はただの文字
- 値の前後の空白は取り除く。正規表現の末尾で空白に当てたいときは `[ ]` を書く
- JSON ではないので、`\d` を `\\d` と書き直す必要はありません。画面に入れた文字列が
  そのままファイルに並びます
- 登録できるのは 20 件まで

**うまくいかないとき**: 多いのは次の 3 つです。

- **行の全部を書いていない。** `^` から `$` まで、行の最初から最後までが当たる形にします
- **空白の数が違う。** レベルの桁を揃えるログでは、`INFO  ` のように後ろが空いたり
  （左詰め。logback の `%-5level` など）、`  INFO` のように前が空いたり
  （右詰め。Spring Boot の `%5p` など）します。空白 1 個ではなく空白 1 個以上（` +`）を
  使ってください
- **角括弧が入れ子になっている。** `[^\]]*` は最初の `]` で止まるため、
  `[pool-1[worker-3]]` のようなスレッド名には一致しません。ガイドの入れ子用の部品を
  使ってください

正規表現が外れていても、この書式には「ヘッダらしさ」の形だけの判定が無いため、
一致しない行はすべて継続行として扱われます。つまり**読み飛ばしの警告は出ず、SQL が
0 件になります**。0 件のときは画面にその旨と手がかりを出すので、「この行で試す」で
確かめてください。

**読めない形式**: 1 エントリが 2 行以上になる前置き、`(?x)`（空白を無視し `#` 以降を
コメントにする書き方。コメントの中に書いたグループをアプリ側が「ある」と数えてしまうため、
取り込み時に書式を示して失敗します）。

**そのほか**:

- 書式は自動判定の候補にも入ります。組み込み書式と同点なら組み込みが選ばれます
- 定義を直すと索引は作り直されます（`id` が同じでも中身が変われば作り直します）
- 書き間違いはその 1 件だけに留まります。読み飛ばした理由は行番号つきで標準エラーに出ます
- ただし**読み飛ばしがある間は、画面からの登録・削除ができません**。書き戻せるのは
  読めた書式だけなので、そのまま保存すると壊れた部分が消えてしまうためです
- 実在しない日時（`2026/02/31`、`24:00:00` など）の行は取り込みません
- 入れ子の量指定子（`(a+)+` のような書き方）は後戻りが爆発します。行の長さに見合わない
  照合は打ち切り、**どの書式のどの行で止めたかを示して取り込みを失敗させます**

**性能**: 正規表現で読むぶん、組み込み書式より解析は重くなります。100 万行
（25 万 SQL ブロック）の索引構築で 1,852ms → 3,836ms（Windows 11 / JDK 8 / -Xmx2g、
交互に 7 回ずつの中央値。同じ内容を書式違いで書いた別ファイル同士の比較）でした。
**この重さを払うのは、この書式を選んだ取り込みだけ**で、組み込み書式の速度は変わりません
（同じ測定で 1,952ms → 1,852ms。1,740〜2,094ms のばらつきの中なので差は無い）。
