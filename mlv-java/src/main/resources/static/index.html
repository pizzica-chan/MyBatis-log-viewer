        書き方ガイド
        
          
          
          考え方
          
          
          
            読みたいログの 1 行をそのまま書き写し、行ごとに変わるところだけを
            「部品」に置き換えてください。これだけです。置き換えた部品に名前を付けると、
            その中身が一覧の列になります。
          
          
          
          
            
          
              ログの行
              2026/06/15 00:19:11.705 DEBUG (main) c.e.UserMapper.selectById : ==>  Preparing: select 1
            
          
            
          
              書き写す
              ^2026/06/15 00:19:11.705 DEBUG (main) c.e.UserMapper.selectById : ==>  Preparing: select 1$
            
          
            
          
              置き換え例
              ^(?<ts>\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}\.\d{3}) (?<level>\w+) \((?<thread>[^)]*)\) (?<logger>\S+) : (?<message>.*)$
            
          
          
          
          
          
            名前は 5 つ決まっていて、ts（日時）と
            message（本文）が必須です。MyBatis の
            Preparing: ・ Parameters: ・ Total: は
            本文から探すため、message を取り出さないと
            SQL が 1 件も見つかりません。
          
          
          
          
            level は任意です。thread と logger も
            任意ですが、この 2 つで SQL ブロックの対応を取っています。
            複数のスレッドが動くログでは必ず入れてください（入れないと、
            別スレッドの Preparing と Parameters が混ざります）。
          
          

          
          部品
          
          
          
            クリックすると正規表現の欄に差し込みます（カーソルの位置に入ります）。
          
          

          
          日時（どれか 1 つを選ぶ）
          
          
          
            
            
            
            
            
            
          
          

          
          レベル・スレッド・ロガー・メッセージ
          
          
          
            
            
            
            
            
            
            
            
          
          

          
          つなぎ・そのほか
          
          
          
            
            
            
            
            
            
          
          

          
          
            行によって出たり出なかったりする部分があるときは、そこを
            (?: と )? ではさみます。たとえば
            --- が付く行と付かない行が混ざるなら (?:--- )? です。
          
          
          
          
            スレッド名が [pool-1[worker-3]] のように、角括弧の中に
            もう 1 組入っているときは、「スレッド [main]」ではなく
            「スレッド [pool-1[worker-3]]」のボタンを選んでください。
            前者は最初の ] で切れてしまい、行に一致しなくなります。
            後者は [main] のような普通の行にもそのまま使えます。
            ロガーが同じ形のときは、このボタンを押してから thread の部分を
            logger に書き換えてください。
          
          
          
          
            ログの中の . [ ] (
            ) + * ? |
            $ ^ \ は、そのままだと別の意味に
            なります。文字として書きたいときは前に \ を足してください
            （. なら \.）。
          
          

          
          日時書式（日時欄）
          
          
          
            ts で取り出した文字列を、どう読むかの指定です。
            正規表現ではなく Java の日時パターンを書きます。
            上の日時の部品を選ぶと、この欄も一緒に入ります。
            正規表現を先に組み立てたいときは、空のままで構いません（その間は
            この行で試すが、取り出せた文字列をそのまま見せます）。
          
          
          
          クリックすると日時書式の欄に入ります
          
          
          
            
            
            
            
            
            
            
            
          
          
          
          
            ts が取り出した文字列と、この日時パターンの形は
            ぴったり合わせてください。区切りが違うだけでも読めません。
            日付を含まない書式（時刻だけ）は、日をまたいだときに並べられないため使えません。
            時刻はログに書かれたままの値として扱い、タイムゾーンの変換はしません。
          
          

          
          うまくいかないとき
          
          
          
            読みたいログを 1 行そのまま「試すログの行」に貼り、この行で試すを
            押してください。各項目に何が取れたか、一致しないときはどこを直せばよいかが出ます
            （登録はされません）。よくある原因は次の 2 つです。
          
          
          
            
            
          • 
              行の全部を書いていない。
              ^ から $ まで、行の最初から最後までが一致する形にします。
              途中で終わっていると一致しません。
            
            • 
            
          • 
              空白の数が違う。
              レベルの桁を揃えるログでは、INFO   のように後ろが空いたり
              （左詰め。logback の %-5level など）、  INFO
              のように前が空いたり（右詰め。Spring Boot の %5p など）します。
              空白 1 個ではなく空白 1 個以上（ +）を使ってください。
            
            • 
          
          

          
          読めない形式
          
          
            
            
          • 
              1 エントリが 2 行以上になる形式。
              一致しなかった行は、直前のエントリの続き（スタックトレース）として扱います。
            
            • 
            
          • 
              (a+)+ のように繰り返しを入れ子にした書き方。
              照合が急激に重くなるため、行の長さに見合わない照合は打ち切り、取り込みを
              失敗させます（画面が固まったままにはなりません）。
            
            • 
            
          • 
              (?x)（空白を無視する書き方）。
              コメントの中に書いたグループを、アプリ側が「ある」と数えてしまいます。
            
            • 
          
          

          
          登録したあと
          
          
          
            書式のプルダウンから選んで 読み込み を押すと、その書式で取り込みます
            （自動判定に任せることもできます）。書式を直すと索引は作り直されます。
            id を変えなくても、正規表現や日時書式を変えれば作り直しの対象です。
